Why the agent waits, and how we stop it

Speed architecture for pi-do file reads, writes, edits, shell exec, and streaming. Lessons from celld, camelAI, and nanocodex, mapped to PR12 + PR27.

2. What celld actually teaches

celld is a self-hosted Durable Objects runtime, not a filesystem. Its value here is measured numbers about where time goes in SQLite-backed objects.

Cloudflare already hands us the fastest row. Our only job: never add a second round trip on top, e.g. awaiting R2 inside a write call. Flush cold bytes in the background instead.

lesson: one owner, no consensus

celld claims a cell with one conditional bucket write. No membership protocol, no failure detector. Our twin is the per-session queue in PR11: serialize at the narrowest point, coordinate nowhere else.

lesson: shed idle, never active

Under memory pressure celld evicts least-recently-used idle cells and never touches live work or open sockets. Our twin: an open WS stream pins its DO. Design for residency, not against it.

lesson: the heap is small (128 MB V8 cap per object)

Bytes must stream through the DO, never buffer in it. Whole-file reads into heap are the bottleneck. Ranges plus streams at every layer is the entire fix.

5. The six rules

1
Split the filesystem DO (PR27). Agent loop never blocks on file I/O. Reads run concurrent; only overlapping writes to the same path queue. This single change removes the biggest stall in section 1.
2
R2 overflow is lazy and async. Writes commit to SQLite and return. A background flush moves cold bytes out. Hot reads never touch R2. The write path stays at DO-local speed forever.
3
Push ranges into storage. SQLite slicing plus R2 range gets, so a 10-line read moves 10 lines, not 1 MB. The read tool already accepts ranges. The store must honor them instead of slicing in JS heap.
4
Batch hot writes in one transaction. Session append, entry frame, and usage counters commit together. Fewer commits means fewer replicated pages means less durability tax per turn.
5
Persistent exec sessions (PR12). Spawn one shell per session, reuse it across bash calls, kill and dispose on envelopes. Process spawn per call is pure overhead with zero agent value.
6
Stream the WS path end to end. Chunked entry frames with backpressure, throttled tool updates, no buffered whole responses in DO heap. The stream is the product surface. It never stalls on bytes.

7. The DO architecture we follow

Cloudflare own rules, condensed. One principle runs everything: scale with more atoms, never bigger atoms. A single object tops out around a thousand requests per second. You do not grow it. You shard it.

never this: one global object
always this: one object per atom of coordination

Each workspace is a two-object shard: agent DO plus fs DO. One workspace hot never slows another. Eviction takes down one pair, never the fleet. This is our topology from §4, now with the scaling argument attached.

colocation is the speed

Compute and SQLite live in the same datacenter, so storage reads cost microseconds, not a network hop. Objects spawn near the first request. Create them from real traffic, never pre-create. Pin placement with locationHint when users cluster in one region, and use jurisdiction only for legal boundaries like eu or FedRAMP.

hibernation is the idle story

The Hibernation WS API keeps sockets open while the object sleeps. No compute billing while hibernating, automatic wake on message. Our stream should use it: an idle agent costs zero, a new frame wakes the pair in milliseconds. Never hold state in memory that SQLite should own, the wake must find everything on disk.

No global DO for shared state. No pre-creating objects off the hot path. No blockConcurrencyWhile around routine work. No in-memory caches that a hibernation wake would miss. Every one of these shows up as a mysterious stall months later.

8. 2026 only: the new powers

Everything below shipped in the last twelve months. This is the mind-blowing part: the platform removed, one by one, every reason agents used to need servers.

Jun 2026 · LLM streams can no longer be evicted mid-thought

Outbound connections keep the object alive

before streaming tokens…EVICTED at 70–140 sdead stream
after stream holds the object alive until it closes (15 min cap)then normal sleep

Our model calls stream over outbound fetch. The agent DO now survives its own longest thoughts by construction. This single change deletes a whole class of resume-and-repair logic.

GA Feb 2026 · 30-day time travel is free

Point-in-time recovery on every object

agent wrecks files bad turn N
recovery restore to N−1replay from entries log

Every workspace DO carries a 30-day rewind button with zero code. Undo for agent damage, audit trail for free, session restore without snapshots. Our entries log plus PITR means no turn is ever truly lost.

Aug 2026 · 10 dynamic workers per DO

Upload code at runtime, run it in isolates beside the object, ten concurrent. The future shape of tool execution: untrusted tool code runs in a disposable isolate, not in the agent heap. Watch this API for the post-bash era.

Oct 2025 · 32 MiB WebSocket messages

Up from 1 MiB. Whole file contents, images, and chunked dumps can ride single frames. Our entry frames will never come near the ceiling, which means framing stays simple.

pi-do wiring plan: unbeatable

Order is dependency order. Each phase is independently shippable and ends in a proof. Rule: no phase starts until the previous phase's proof is green.
Design target: survive everything cf survives, keep everything we already do, stay under ~800 lines of new wiring (their base class alone is ~5k). Smallness is the moat. Every item below names its proof or it does not ship.

Phase 0: measure first

Baselines before any wiring changes

Every later claim needs a before number. No production code changes in this phase.
  1. Eviction repro script: idle out a DO mid-turn, record exactly what is lost. Depends on: nothing. Proof: script prints LOST with entry/delta inventory.
  2. Stage timing: extend the usage row with sqlMs, inferenceMs, frameMs per turn. Depends on: nothing. Proof: keyed-runtime prints the split.
  3. Turn cost census: SQL ops per turn, rows written, bytes per entry. Depends on: item 2. Proof: one table in the next commit message.
Risk: none. Scripts and columns only.

Phase 1: survival (the heartbeat)

Keepalive during executeTurn

Single highest-impact change. Ref-counted alarm re-arm at +30s while a turn holds it, released in finally. Eviction stops being a silent killer.
  1. Hold/release around executeTurn using the existing alarm slot. Depends on: Phase 0 item 1 (know the enemy). Proof: eviction repro now shows HELD, turn completes.
Risk: alarm slot contention with compaction. Mitigation: re-arm takes max(compactionAt, keepaliveAt), never overwrites an earlier deadline.

Phase 2: durability (the chunk log)

Two grains: ledger plus log

Keep pi_entries exactly as is. Add pi_chunks(sid, turnId, seq, body) written per streaming delta, tagged by turn id. Recovery replays the log, everything else reads the ledger.
  1. Schema + append in the event emission path (emitEntry neighborhood). Depends on: Phase 1. Proof: kill -9 mid-turn leaves queryable deltas.
  2. Flush policy starts at every-delta (correct first, cheap later). Proof: Phase 0 census shows write cost, feeds Phase 6 tuning.
Risk: write amplification on fast models. Mitigation: census-gated; packing comes in Phase 6 with numbers.

Phase 3: resurrection (recovery)

Wake scan, classify, suffix-continue, merge

The theft from cf, adapted to tools. Preserved partial excluded from model context, model primed with suffix only, merge folds onto prefix.
  1. Preserve-partial flag on entries + wake scan in constructor path. Depends on: Phase 2. Proof: restart after kill shows PARTIAL row.
  2. Classify continue vs retry; suffix-continue in model-runtime; merge with byte math. Proof: SIGKILL e2e, prefix+suffix == full reply.
  3. Tool-aware continuation: settled tool results re-attached from the ledger, only unsettled calls re-execute, fence idempotency keys per call. Depends on: item 2. Proof: SIGKILL mid-tool-turn resumes without double-executing bash. This is the move cf cannot make.
Risk: suffix priming changes model output (non-deterministic suffix). Mitigation: byte math asserts merge integrity, not model determinism; refusal/paraphrase falls back to retry.

Phase 4: background discipline

Ledgered turns, multiplexed alarm, bounded retries

Replace memory-only coordination with rows the alarm can heal.
  1. pi_runs ledger: row at turn start, delete at commit, stash snapshot of fence + cursor. Depends on: Phase 3. Proof: orphaned row queryable after kill, healed on wake.
  2. Alarm mux: one slot, job table (keepalive, compaction, recovery scan), earliest-deadline wins. Proof: all three fire under a single slot, no starvation in logs.
  3. Poison aging + exponential backoff on the scan. Proof: wedged-turn fixture backs off, DO stays responsive.
  4. Chunk reaping inside the compaction cutover transaction. Proof: storage census flat across 10 compactions.
Risk: alarm mux starves compaction under constant turns. Mitigation: compaction has a max-age deadline that preempts keepalive re-arms.

Phase 5: structure

Seam split + minimal base

Only after behavior is proven. Refactors ride on green proofs, never alongside them.
  1. Split stream.ts into codec (frames in/out) and engine (turn policy, recovery). Zero behavior change. Depends on: Phase 4 green. Proof: full battery green, diff is moves only.
  2. Extract ~300-line DO base (fetch table, alarm mux, SQL + retry helpers). WorkspaceDO becomes thin. Proof: battery green, second DO could mount it (prove by mounting eviction-e2e DO on it).
Risk: refactor churn for aesthetics. Mitigation: strict moves-only diffs, battery as gate.

Phase 6: perf (beat cf)

Measured speed, not hoped speed

cf never had to be fast (faux model). We do. Every item needs a Phase 0 number first.
  1. Adaptive flush: pack deltas into boundary-aware segments (their 10-chunk packing, tuned by our census). Depends on: Phase 0 census + Phase 2. Proof: writes-per-turn down, SIGKILL proof still green.
  2. Hot-path SQL: indexes on (sid, cursor), prepared reuse in append + tail reads. Proof: sqlMs down in usage rows.
  3. WS frame batching + context-build cache across polls. Proof: frameMs down, byte-identical replays.
Risk: premature optimization. Mitigation: numbers first, each item re-proven by the kill suite (fast must never weaken durability).

Phase 7: lock it

Chaos battery

Gains rot without a guard.
  1. Keyed tier gains eviction-e2e + SIGKILL-e2e + quota-refusal scripts. Depends on: Phases 3, 4. Proof: tier green with kills in it.
  2. Nightly long-soak: 100 turns, compactions, kills, storage census flat. Proof: morning report, zero orphans, flat storage.
Non-goals, stated so they stay out. No framework base class (their 5k lines are the anti-target). No engine import from agents (fights the harness). No compaction redesign (ours already wins). No new provider work.

Merge order + lane rules

How waves collapse back to main

  1. Merge mux first. Re-proof: fast tier + eviction repro HELD. Heartbeat without the mux would re-fight compaction for the slot.
  2. Merge chunks second. Re-proof: kill-leaves-deltas + fast tier. Recovery lane rebases onto it; until then it builds against the Wave 0 schema contract.
  3. Merge recovery third. Re-proof: SIGKILL byte-math + full keyed tier. Tool-aware continuation lands in the same merge, same proof.
  4. Merge ledger fourth. Re-proof: orphan-heal + storage census flat + tiers.
  5. Merge shape last. Re-proof: full battery + kill suite, moves-only diffs for the seam split.
Rules. Lanes coordinate through hub before touching any shared region of stream.ts. A lane that needs a contract change stops and returns to root instead of improvising. Root never merges a lane whose stated proof is red. Perf tuning (Phase 6) starts only after Wave 4, with census numbers in hand.
Wall-clock shape: Wave 1 runs 4 lanes at once (proof, mux, chunks-schema, census). Wave 2 runs recovery, ledger, and SIGKILL scripting at once. The critical path is contracts -> mux -> chunks -> recovery -> shape. Everything else rides alongside it.
